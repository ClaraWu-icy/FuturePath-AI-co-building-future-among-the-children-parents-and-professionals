# FuturePath AI · 青少年 AI 生涯规划平台

> 面向青少年与家长的生涯探索工具。学生通过对话、情景任务与职业体验积累**可追溯的证据**，
> AI 生成带证据引用的成长画像与 5—10 年规划，家长参与讨论，专业版加入真人规划师审核并讨论。
>
> 流程：**两份量表 → 个人画像 → AI 初步方案 → 多方讨论修改 → 最终方案**（见 2.1 节）。

当前版本：**v0.1.0 MVP**，零第三方依赖，`npm start` 即可运行，无需安装任何包。

## 2. 网页简介

### 学生端
- **流程页（首页）**：登录后第一屏不是表单，而是「你在第几步」——五步时间线 + 进度环 + 当前该做的事（详见 2.1 节）。
- **对话探索**：8 组动态提问，按"证据最少的维度"选择下一个问题；短回答触发追问，不会直接定性。
- **情景任务**：6 个情境（科技节 / 班级活动 / 修收音机 / 社区课堂 / 成绩分析 / 小组分歧），选项同时映射兴趣与能力。
- **兴趣卡片**：18 张"愿不愿意花时间做"的两选项卡片。
- **职业体验**：22 个职业，含工作现状、学习路径、相关学科、**零成本体验任务**、现实限制与免责说明；自评 1—5 分入库。
- **成长画像**：六维雷达（实践动手 / 探究思考 / 创意表达 / 助人沟通 / 组织影响 / 条理执行）、能力条形图、价值观标签、优势（带 E1…En 证据编号）、待验证假设、候选发展方向（匹配度 + 短板 + 路径）、成长建议、局限说明、版本历史；顶部有**「量表说了什么：兴趣与潜力」**卡片（兴趣条形 / 潜力条形 / 叙述 / 学习方式建议）。
- **确认 / 异议**：任何优势或假设都可以"我认同 / 我不认同"，异议会**下调该证据权重**并留痕。
- **发展规划**：5 年或 10 年，包含愿景、发展摘要、3 条路径、**A/B/C/D 四阶段路线图**（目标 / 行动 / 成果 / 资源 / 替代路径 / 指标 / 复盘时间 / 调整条件）、日常行动、风险、支持系统、规划师意见、双方确认记录、版本历史；可在线编辑（生成新版本）、导出 Markdown / HTML、打印或存为 PDF；方案下方内嵌**讨论区**与**定稿检查表**。

### 2.1 主流程：注册 → 两份量表 → 画像 → 初步方案 → 讨论 → 最终方案

流程是固定的五步，页面在 `/start`（侧栏「流程」），也是学生登录后的首页横幅。每一步都**由已有记录推导**，没有单独的流程表，所以不会出现"界面说完成了、数据里其实是空的"。

| # | 步骤 | 完成目标 | 参与者 |
| --- | --- | --- | --- |
| 1 | 做两份量表 | 霍兰德 + 多元智能**都有**一份作答 | 学生本人（家长 / 规划师不能代答） |
| 2 | 生成个人画像 | 存在一份**不早于**最新量表时间的 `analysis` | 自动：第二份量表提交时立刻生成 |
| 3 | AI 初步方案 | 存在一份 `status=draft` 的规划 | 自动：画像生成后立刻生成 |
| 4 | 多方讨论 | 学生与家长都发过言（有派单时再加规划师审核意见） | 学生 / 家长 / 规划师 |
| 5 | 形成最终方案 | 方案有 `finalizedAt`（不是"已确认"，是**定稿**） | 学生或家长点定稿 |

关键设计：

- **答完不需要再点两次「生成」**。提交第二份量表的响应里直接带回 `journey`（含画像 id 与方案 id），前端据此跳到结论页；重复作答只重算画像、**不再覆盖已有方案**（避免学生重测一次就丢掉讨论记录）。
- **方案有明确的生命周期**：`draft`（初步方案）→ `discussing`（讨论中）→ `pending_confirm`（待确认）→ `confirmed`（已确认）→ 定稿写 `finalizedAt` 才是**最终方案**。每次编辑生成新版本，旧版本标 `superseded` 并保留，不是覆盖。
- **讨论留痕，AI 只整理不动手**：每条意见落入 `planComments`（带作者角色与版本号），AI 逐条回应、标明识别到的议题（时间冲突 / 预算 / 现实性 / 不认同等）并给出降档建议，但**不会自己改方案**——改动必须由人点「编辑方案」写入，生成新版本后重新走确认。
- **定稿有三道条件**：学生确认 + 家长确认 + （若这个档案已派了真人规划师）规划师已提交审核意见。缺项会在按钮上方逐条列出，接口返回 `400` 并说明缺什么；规划师调用定稿接口一律 `403`——他提交的是审核意见，不是代替家长签字。
- **权限边界**：家长与规划师可以看流程进度、可以发言，但不能作答量表、不能代学生确认、不能定稿。

接口：

```
GET  /api/students/:id/journey        五步状态、进度、量表摘要、方案阶段与定稿条件
POST /api/assess/:scale               提交量表 → 返回 journey（量表齐了就带画像与初步方案）
GET  /api/plans/:id/comments          讨论串（按时间正序）+ 各角色条数 + 定稿条件
POST /api/plans/:id/comments          发一条意见 → 落库 + AI 回应 + draft 推进为 discussing
POST /api/plans/:id/finalize          定稿（仅学生 / 家长；条件不足 400，列出缺失项）
```

### 启程引导（可选的七个问题 → 第一版画像）

七问原本是第一次进入的必经动画，现在**不再拦在流程前面**——量表才是第一步。
它被保留为"不想做题时的另一条入口"：首页「重看启程」，或带 `?intro=1` 打开首页；新档案可从落地页选择。

学生会被问到**七个具体问题**——兴趣、擅长、遇到事怎么做、选方向时在意什么。
**答完当场出第一版个人画像。**

| # | 问题 | 问的是什么 |
| --- | --- | --- |
| 1 | 一整天没人安排，你最可能怎么过 | 兴趣的起点（动手 / 查资料 / 做东西 / 找人 / 运动 / 整理） |
| 2 | 最近半年你主动去了解过什么 | 兴趣的深度：愿不愿意为它多走半步 |
| 3 | 别人最常找你帮什么忙 | 能力的外部证据（别人的真实选择，比自评可靠） |
| 4 | 哪件事你做起来不费劲 | 能力的内部感受（不是"做得好"，是"不费劲"） |
| 5 | 小组作业快交了，有人一直没交，你会怎么做 | 情境判断：面对别人的失误 |
| 6 | 学一样新东西，练了两周还是很难看，你会怎么做 | 情境判断：面对自己的瓶颈 |
| 7 | 选科 / 选专业时，你最在意哪一条 | 价值取向（稳定 / 创造 / 搞明白 / 帮到人 / 自由 / 成绩） |

- **每问 5–7 个具体选项**，全部是生活里会发生的事，没有一道是"你适合什么职业"。
  每题还能补一句自己的话，留空也能过。
- **不设引导性提问**：选项没有分值、没有"正确答案"的暗示；选完导师给一句贴着这个选择的回话，
  并且一定带一句"代价"（例：选了"自己把他的部分做了"，回的是"短期最有效，长期你会变成什么都能兜的那个人，而别人一直学不会"）。
- **作答写进证据库**：每问落 1–2 条 `signals`（兴趣/情境类 `dialogue`，价值观类 `value`），
  学生的原话同时进 `conversations`；画像里的每条结论都挂着 `E1…En` 证据编号。
- **第七问答完立刻生成画像**：直接复用正式分析链路（同一套打分、同一份证据索引），
  当场给出六维条形、目前最清楚的两条、还不确定的两条、可以先了解的方向、以及局限说明。
  画像页读到的就是同一个 `analysis`（不会出现"动画里一套、报表里另一套"）。
- **可跳过 / 可续播 / 可重看**：右上角"跳过"有二次确认；中途关掉下次从没答完的那一问继续；
  首页"重看启程"**不重复计分**（同一问只记一次，换选项只回放不叠加）。
- **页面简洁**：纯 CSS 动画 + 内联 SVG，零图片零视频；`prefers-reduced-motion` 与低带宽模式
  自动关掉星星、打字机、飞入和条形增长动画；键盘 `1–7` 选择、`Enter` 继续、`Esc` 跳过，句子挂在 `aria-live` 上。

截图见 `docs/screenshots/`（序幕 / 第一问选项 / 第一版画像 / 移动端）。

这条入口对访客同样开放：落地页选「先不注册，直接做两份量表」进主流程（见 0.1 节），
访客拿到的是带 `guest` 标记的临时档案，走的完全是同一条接口与同一套分析链路。

### 标准化测评（霍兰德 RIASEC + 多元智能）

探索回答是"具体发生的事件"，量表回答是"结构上分类"。两者互补，所以做成两套独立的工具。
**这两份量表是主流程的第一步**（见 2.1 节），入口在侧栏「标准化测评」，也可以从首页的测评卡片进入。

| 工具 | 理论来源 | 结构 | 输出 |
| --- | --- | --- | --- |
| 霍兰德职业兴趣量表 | Holland《Making Vocational Choices》(1997) 六类型模型 | 6 类 × 6 题 = **36 题**，5 点 Likert | 六维分数（0–100）、**三字代码**（如 `IAR`）、区分度、一致性 |
| 多元智能自评 | Gardner《Frames of Mind》(1983) 八项智能 | 8 项 × 5 题 = **40 题**，5 点 Likert | 八项相对强弱、前三项解释、学习方式建议 |

- **以具体活动为题目**：例如"把坏掉的台灯拆开试着修好"（R）、"给同学讲题直到他真的听懂"（S）。
  每题五个选项：完全不像我 / 不太像 / 一半一半 / 比较像 / 非常像我。
- **维度归属不下发前端**：接口只返回题干与序号，`dims` 留在服务端，防止学生按"哪个分高"作答。
- **计分可复现**：单维 `(得分和 − 题数) / (4 × 题数) × 100`，即 0–100；另算组内 z 分数用于相对强弱与排序。
  三字代码取原始分前三（并列按 R→I→A→S→E→C 固定顺序）。
- **给出质量指标，避免只给一个分数**：
  区分度（最高与最低类型的分差）、一致性（前两型在霍兰德六边形上的距离：相邻 / 间隔一位 / 相对）、
  同维度内部作答题目的标准差（太小＝在快速勾选，太大＝可能没读懂题）。全部同档会被判为无效并要求重测。
- **结果进入证据库**：每一维写一条 `source=assessment` 的证据（RIASEC 记在该维度、多元智能记为 `MI`），
  `meta.items` 记录题量。画像聚合时按题量折算证据充分度——**档案里只有量表证据时，画像的六维分数就等于量表百分比**；
  和对话、情景任务合并后分数会变，但每条证据都能追溯到具体题量与满分，不会出现"量表说 96、画像却记 40"的错位。
  重测会替换上一次的量表证据，不叠加；历史仍保留在 `assessments` 里可对比。
- **不合成总分**：多元智能只排相对强弱，不给"总智商"式的分数；霍兰德也只描述结构，不排名高低。
- **答完自动接上后面两步**：第二份量表提交的响应里直接带 `journey`，画像与初步方案当场生成，
  结果页下方就给入口（不用再手动点两次"生成"）。重测只重算画像，**不覆盖已有方案**，讨论记录不会丢。

明确写进结果页的边界：

> 两套都是**自评**，不是能力测验，不预测成绩与收入，不能用于诊断、分班或评价他人。
> 多元智能理论在学界仍有争议（八项智能是否彼此独立缺少充分实证），这里只把它当作"描述自己怎么学更顺"的框架。

接口：

```
GET  /api/assess                     两份量表的元信息 + 作答次数 + 上次结果摘要
GET  /api/assess/:scale?studentId=   题目（36 / 40）、五档选项、已答次数
POST /api/assess/:scale              提交作答 → 计分、写证据、存档案、返回结果与职业对照
GET  /api/assess/:scale/result       最近一次结果 + 历史
```

权限：学生本人可作答；家长 / 规划师只能查看，代答返回 403；跨档案读取 403。
作答进度暂存在本机 `localStorage`，刷新或中途退出可以接着答，提交后清除。

### 家长端
- 孩子概览：进度、证据来源分布、AI 当前结论、**"你的观察 vs 孩子的自评"对照**。
- 补充家庭观察 → 直接成为一条 `parent` 来源证据（权重高于普通自述，但不能改写学生原始回答）。
- 与 AI 结构化讨论：AI 会明确指出"你的说法与证据一致/冲突"，并给出一条具体追问；家长发言同时入库为证据。
- 记录家长期待、可提供资源、担忧。
- **在方案上直接提意见**：方案页的讨论区里家长可以就具体阶段提约束（预算、成绩、时间），
  AI 会把它当约束条件记下来并给可执行的降档建议；家长的意见与学生的意见、AI 的回应一起留痕。
- **与孩子共同定稿**：学生 + 家长都确认后才可点"定稿"，定稿后方案才叫「最终方案」；家长也可以先看进度页知道自己卡在哪一步。

### AI 导师端（学生 / 家长均可进入）
- 引擎状态、打分方式、数据来源、结论溯源方式。
- 全量看板：待验证假设数、需要重新分析的档案、学生提出的异议、每个学生的"下一步建议"。
- **能力边界说明**：会做什么 / 不会做什么（不据单次选择定职业、不用地区家庭条件限制可能性、不编造时效数据、不冒充真人）。

### 规划师端（专业版，目前尚未实现）
- 队列 → 接单 → 查看**专业讨论材料**（阶段、数据范围、前三兴趣、价值观、学生不认同的结论、候选路径、材料缺口、需重点判断的问题）→ 核对**原始证据** → 提交审核意见（总体评估 + 修订项 + 修订理由 + 风险 + 下一步）。
- 提交后：方案写入"真人规划师意见"、`professionalReviewed = true`、版本 +1，并记录审核人与资质。
- 资质未审核的规划师无法接单；只有实际提交过意见才会出现"已审核"标记。
- **规划师的审核是定稿的前置条件**：档案一旦派了单，方案未审核时学生与家长即使都确认也无法定稿
  （接口返回 400，`missing` 里写明缺"真人规划师审核意见"）。反过来，规划师**不能**代替任何一方确认或定稿，调用一律 403。

### 公益 / 隐私
- 公益服务页：项目列表（**明确标注演示数据**）、邀请码登记、低带宽适配说明、本实例统计。
- 隐私页：5 项授权独立开关（监护人 / 数据使用 / AI 分析 / 向规划师共享 / 公益参与）、JSON 全量导出、二次确认删除、操作审计日志、存储与保留说明、AI 使用说明。
- 低带宽模式：关闭动画、阴影、渐变，保留全部文本流程；可在侧栏随时切换。

## 3. AI 接入状态（重要）

| 项目 | 当前状态 |
| --- | --- |
| 默认模式 | **模拟模式（simulated）**：内置可解释规则引擎，**未调用任何大模型** |
| 是否假装调用 | 否。页面顶部与接口 `GET /api/ai/status` 都会明确返回 `mode: "simulated"`、`live: false` |
| 打分来源 | 本地计算：证据加权（强度 × 权重 × 学生确认状态）+ 去均值余弦相似度（Pearson） |
| 文本来源 | 规则模板（模拟模式） |
| 真实模型 | 可选接入任意 OpenAI 兼容接口，配置环境变量即可切换 |

**接入真实模型的步骤**（不配置则完全不影响运行）：

```bash
export AI_PROVIDER=openai
export OPENAI_API_KEY=sk-...
export OPENAI_BASE_URL=https://api.openai.com/v1   # 可换成任意兼容网关
export OPENAI_MODEL=gpt-4o-mini
npm start
```

设计约束：模型**只负责把结构化事实写成自然叙述**（summary 与 3 条建议、家长讨论回复），
评分、证据引用、假设与路径仍由本地引擎计算，模型失败/超时会静默回退到规则文本，
不会出现"假装调用成功"。

## 4. 技术栈与结构

- **运行时**：Node.js ≥ 20（仅标准库：`http` / `crypto` / `fs`），无 npm 依赖
- **后端**：自建微型路由 + 服务层 + 规则引擎，`server/`
- **前端**：原生 ES Modules + 手写 CSS 设计系统（无构建步骤、无框架），`public/`
- **数据**：JSON 文件（`data/db.json`），原子写入（临时文件 + rename）、30ms 防抖
- **鉴权**：HMAC 签名 Token（Bearer），scrypt 加盐密码哈希，基于角色的访问控制

### 数据模型（JSON 集合 → 未来关系表）

| 集合 | 对应实体 | 关键字段 |
| --- | --- | --- |
| `users` | 账号 | `role`, `passwordHash`, `salt`, `verified`, `credential` |
| `students` | Student | `ageBand`, `grade`, `region`, `plan(free/pro)`, `guardianId`, `lowBandwidth` |
| `signals` | InterestProfile + SkillEvidence + ValueProfile + ParentFeedback（统一证据表） | `source`, `dimension`, `strength`, `weight`, `excerpt`, `ability`, `selfEval`, `studentFeedback` |
| `conversations` | Conversation | `kind(explore/discussion)`, `question`, `answer`, `reflection`, `role` |
| `exploreSessions` | ExplorationSession / CareerExperience | `kind`, `itemId`, `choice`, `selfEval`, `signalIds` |
| `analyses` | AIAnalysis | `signalCount`, `dataRange`, `summary`, `strengths[]`, `hypotheses[]`, `careerMatches[]`, `evidenceIndex[]`, `acknowledgements[]` |
| `plans` | CareerPlan + PlanMilestone | `version`, `horizon`, `sections{summary,paths,phases,actions,risks,support}`, `status(draft/discussing/pending_confirm/confirmed/superseded)`, `confirmations[]`, `professionalReviewed`, `finalizedAt`/`finalVersion` |
| `planRevisions` | PlanRevision | `version`, `by`, `byName`, `changedFields`, `note` |
| `planComments` | PlanComment（方案讨论留痕） | `planId`, `version`, `role(student/parent/advisor/ai)`, `byName`, `kind`, `text`, `meta{topics}` |
| `professionalReviews` | ProfessionalReview | `assessment`, `corrections[{target,reason,revised}]`, `risks[]`, `credential` |
| `advisorSessions` | 服务单 | `status(queued/claimed/reviewed/completed)`, `advisorId` |
| `consents` | ConsentRecord | `type`, `granted`, `scope`, `attestedBy`, `at` |
| `auditLog` | AuditLog | `action`, `actorRole`, `meta` |
| `orders` | 订单（演示） | `status: demo_activated`, `demo: true` |
| `welfareRecords` | 公益参与记录 | `programId`, `code`, `demo: true` |

设计要点：
1. **原始记录与分析结果分开存储**：`signals` 永不被改写，分析只引用其 id。
2. **结论可追溯**：分析生成时把引用到的证据编号化为 `E1…En`，前端点击即可看原文。
3. **画像 / 规划都有版本**：规划每次编辑 `version + 1` 并写入 `planRevisions`，旧版本保留（`superseded`）。
4. **学生可以不同意**：`studentFeedback.status = disputed` 会把该条证据权重乘以 0.35。
5. **流程状态不落库**：五步旅程的每步完成与否都由 `assessments` / `analyses` / `plans` / `planComments` / `advisorSessions` 实时算出（`services/journey.js` 是纯函数），
   因此不存在"流程表说完了、数据里没有"的分叉，也不需要修复脚本。

## 6. 尚未完成 / 已知限制

1. **存储**：JSON 单文件，适合演示与单机，不适合多实例部署；写入有 30ms 防抖，进程被 `kill -9` 时可能丢失最后一批写入。迁移点已隔离在 `server/db.js`。
2. **鉴权**：自签 HMAC Token，无刷新令牌、无找回密码、无邮箱/短信验证；生产需接入正规身份体系。
3. **支付**：仅有演示开通，没有真实订单状态机、退款、发票。
4. **规划师身份核验**：仅用 `verified` 布尔字段模拟，没有资质材料上传与人工审核后台。
5. **PDF**：通过浏览器"打印 → 存为 PDF"实现，没有服务端 PDF 渲染。
6. **通知**：没有邮件/短信/站内提醒，"每 8 周复盘"目前是文案建议而非定时任务。
7. **无障碍**：已做键盘可达、焦点样式、错误文字提示、对比度；尚未做完整屏幕阅读器回归与 WCAG 审计。
8. **公益合作**：所有机构、项目、名额、统计均为虚构演示数据，未接入远见平台或任何外部系统。
9. **数据保留策略**：删除立即移除主记录，但未实现自动过期清理任务。
10. **国际化**：仅简体中文。

## 8. 演示脚本（建议 8 分钟）

**0. 主流程五步（2 分钟，最有说服力的一段）**
1. 打开落地页 → 点「先不注册，直接做两份量表」→ 直接进流程页，五步里只有第一步是亮的。
2. 先只答完霍兰德（36 题）→ 结果页下方提示"还差一份"，画像与方案**不会**提前生成。
3. 接着答完多元智能（40 题）→ 提交后**当场**跳到结论：进度 60%，画像和初步方案已经在了（不需要再点任何"生成"）。
4. 方案页往下拉到讨论区 → 学生说"每周两次做不到、预算 2000 以内" → AI 立刻回应、标出议题并给降档建议，
   但明确说"我不会自己改方案"；状态从「初步方案」变「讨论中」。
5. 直接点定稿 → 被拒，按钮下方逐条列出缺「学生确认」「家长确认」。
6. 学生确认 → 切 `parent_a` 确认 → 此时状态是「已确认」而不是「最终方案」→ 点定稿 → 变「最终方案」，记 `finalizedAt`，进度 100%。
7. 用 `counselor` 试定稿苏念的方案 → 403（规划师提交审核意见，不代替家长签字）。

**A. 公益版闭环（学生 xiaoyu）**
1. 流程页（`#/start`）→ 五步全部完成，进度环 100%，点每条能看到落到哪条记录。
2. 探索 → 对话探索：输入一段具体经历，观察 AI 的追问与右侧雷达实时变化。
3. 情景任务 → 选一个选项，看"AI 观察"如何强调"这只是特定情境下的选择"。
4. 标准化测评 → 霍兰德结果页：三字代码 `IRA`、区分度 67、一致性"高（相邻类型）"、职业对照为什么给 84%；
   再点"多元智能"看八项相对强弱（不给总分），最后说明"两套都是自评，不是能力测验"。
5. 成长画像 → 顶部「量表说了什么」看兴趣/潜力条形与学习方式建议；点证据编号 `E1` 看原文；
   对一条优势点"我不认同"，看权重下调提示。
6. 发展规划 → 看到讨论区里已有的 4 条记录（学生 / AI / 家长 / AI）→ 编辑愿景 → 保存为新版本（v2，重新走确认）→ 导出 Markdown。
7. 切到 `parent_a` → 补充一条家庭观察 → 与 AI 讨论"他爱拆东西但不爱写作业"。

**B. 专业版闭环（家长 parent_b → 规划师 counselor）**
1. 用 `parent_b` 打开苏念的报告，指出"已由真人规划师审核"与审核人资质。
2. 用 `counselor` 打开服务单，展示专业讨论材料、待判断问题、修订理由与原始证据。
3. 说明：若资质未核验，接单会被拒绝；AI 不会被标记为已完成真人审核；有派单但未审核的档案定不了稿。

**C. 反面演示（体现产品原则）**
1. 新建一个空学生 → 生成分析被拒绝（"至少 3 条证据"）；流程页五步只有第一步亮着。
2. 用家长账号尝试替学生答题 → 403；家长访问别人孩子的流程页 → 403。
3. 讨论区里家长说"他就是不爱学习" → AI 要求具体事例，不附和标签。

## 9. 下一阶段建议

1. **换数据库**：PostgreSQL（或 SQLite 过渡），把 `signals` 拆成 `interest/skill/value/observation` 四表，加索引与迁移脚本。
2. **真实模型接入**：为"追问生成"和"分析叙述"分别设计 prompt 与 JSON Schema 校验；加入 token 计量与内容安全过滤。
3. **规划师后台**：资质材料上传、审核队列、服务评价、排期与工单 SLA。
4. **复盘机制**：定时任务（cron）生成阶段复盘提醒，把"目标完成情况"回写为一条新证据。
5. **低带宽与离线**：Service Worker 缓存 + 静态资源内联；纯文本降级页面。
6. **测量效度**：对 6 维打分做重测信度与跨群体偏差检验（尤其地区与资源差异），避免把机会差异算成能力差异。
7. **无障碍与合规**：WCAG 2.1 AA 审计、未成年人个人信息保护影响评估（PIPIA）、数据保留与删除的自动化。
